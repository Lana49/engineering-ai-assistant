# Инженерный помощник по строительной документации

Учебный RAG-проект для поиска по строительной документации и проверяемых инженерных расчётов. Интерфейс — Streamlit, размещение — Hugging Face Docker Space. Для генерации используется локальная Ollama. Внешние LLM API и ключи не нужны.

## Как получается ответ

1. Парсер читает PDF, DOCX, RTF и DOC, разбивает текст на фрагменты и сохраняет сведения об источнике. PDF-сканы требуют OCR. Таблицы сохраняются, если их структуру удалось извлечь.
2. Вопрос разбирается: тема, номер документа, пункт, расчёт или справочная информация, известные параметры и единицы.
3. Поиск объединяет TF-IDF и эмбеддинги `paraphrase-multilingual-MiniLM-L12-v2`. Векторные оценки вычисляются NumPy; FAISS в этом пути не используется.
4. Определения и нормативные ответы выводятся точными выдержками; для определения требуется прямое определение термина, одной библиографической ссылки недостаточно. При нехватке свидетельства бот просит уточнение. Для обычных объясняющих вопросов Ollama получает найденные фрагменты; если модель недоступна или ссылки некорректны, интерфейс показывает подписанные выдержки.
5. Поддерживаемые расчёты выполняет Python: параметры → проверка единиц и диапазонов → формула → результат. Модель не подставляет выдуманные исходные данные.

Бот не помещает все документы одновременно в контекст модели: он сначала ищет подходящие фрагменты. Полнота чтения, поиска и правильность вывода — разные проверки. Наличие номера источника само по себе не доказывает правильность каждого вывода LLM.

## Локальный запуск

Используйте существующее работающее окружение проекта. При создании нового окружения для закреплённых версий из `requirements.txt` используйте Python 3.10 или 3.11, как в Docker; не устанавливайте старые пины в Python 3.14.

В подготовленной копии PyCharm используйте существующий `.venv` и уже установленную `llama3.1:8b`:

```bash
bash start.sh
```

Откройте `http://localhost:7860`. Скрипт выбирает `.venv/bin/python`, загружает настройки и проверяет Ollama. Прямой запуск из PyCharm также поддерживается: модуль `streamlit`, параметры `run app.py`, рабочая папка — корень проекта.

Для нового окружения зависимости устанавливаются отдельно: `python -m pip install -r requirements.txt`. Существующее рабочее окружение переустанавливать не требуется.

Настройки читаются из переменных окружения, затем `.env`, затем `op.env`; переменные окружения имеют приоритет. Пример содержится в `.env.example`. Для уже установленной модели можно задать, например, `OLLAMA_MODEL=llama3.1:8b` в `.env` или `op.env`. Установленные модели показывает `ollama list`. Сервер Ollama и модель — отдельные компоненты: работающий сервер не означает, что нужная модель скачана.

Индекс сохраняется в `data/processed/faiss_index.pkl` (историческое имя сохранено для совместимости) и загружается при следующем запуске. Если данных и индекса ещё нет, нажмите «Скачать датасет», затем «Перестроить индекс». После изменений парсера и алгоритма поиска перестройте старый индекс.

Кэш эмбеддингов в `data/embeddings` подхватывается автоматически; другой путь задаётся `SENTENCE_TRANSFORMERS_HOME`. Локальные документы, кэш и индекс исключены из Git и Docker-контекста. Из своего сохранённого результата чтения можно построить индекс без повторного OCR:

```bash
.venv/bin/python tests/build_full_index.py --parsed data/processed/parsed_documents.json
```

## Hugging Face

Датасет: [Lana49/engineering-docs](https://huggingface.co/datasets/Lana49/engineering-docs).

В репозиторий Space загружается код. Пустая `data/raw` в репозитории допустима: `snapshot_download` скачивает файлы при работе приложения. `.dockerignore` исключает локальные документы, модели, окружения и настройки из Docker-образа.

Docker включает `AUTO_SYNC_DATASET=true` и `AUTO_REBUILD_INDEX=true`: на первом запуске скачиваются документы и строится индекс, а следующие запуски используют сохранённый индекс, пока доступен диск. На бесплатном эфемерном диске после пересоздания Space подготовка может потребоваться снова. Для ручной подготовки установите обе настройки в `false` и используйте кнопки интерфейса.

Начальное скачивание моделей и индексация значительно медленнее обычного запроса. Скорость генерации зависит от размера модели и оборудования Space. Если Ollama не запустилась, поиск и детерминированные расчёты продолжают работать, а ответы помечаются как выдержки без генеративного анализа.

Системные программы для PDF OCR и DOC уже перечислены в Dockerfile: Tesseract с языками `rus` и `eng`, antiword, catdoc. На macOS для старых DOC также доступен системный `textutil`. Экспорт русского PDF использует DejaVu Sans (Docker) или Arial (macOS/Windows).

## Примеры проверки

- `Что такое рециркуляция воздуха по СП 60.13330?`
- `Что требует пункт 7.2.2 СП 73.13330?`
- `Рассчитай вентиляцию: L=100 м³/ч, t_в=20 °C, t_н=-25 °C` — ожидается 1507,5 Вт.
- `Рассчитай сопротивление слоя: толщина 100 мм, λ=0,04` — ожидается 2,5 м²·°C/Вт.
- `Рассчитай теплопотери: A=10 м², R=2,5, Δt=45` — ожидается 180 Вт.
- `Рассчитай ГСОП: t_в=20, t_от=-8,4, z_от=225` — ожидается 6390 °C·сут.

Числа в последних примерах — контрольные исходные данные тестов, не климатические нормативы для конкретного города. Для расчёта по городу нужна однозначно подписанная климатическая таблица или заданные пользователем параметры. Встроенные неподтверждённые климатические значения по умолчанию отключены.

## Проверки кода

```bash
USE_LLM=false USE_EMBEDDINGS=false AUTO_SYNC_DATASET=false AUTO_REBUILD_INDEX=false python -m unittest discover -s tests -v
python app.py --self-test
python -m core.query_parser
python -m core.formula_engine
bash -n start.sh
```

Обычные unit-тесты не скачивают модели и не требуют Ollama. Тесты реального корпуса пропускаются, если соответствующие документы ещё не скачаны. Ручная проверка настоящего семантического поиска и LLM:

```bash
python tests/validate_runtime.py --document 'data/raw/СП 60.13330.2020.docx' --model llama3.1:8b
```

Результат этой проверки записывается в `data/processed/runtime_validation.json`. Ошибки чтения документов, поиска и обращения к модели видны в терминале/логах Space; статус индекса и модели показан в боковой панели.

## Границы проекта

Сложные сканированные и многоуровневые таблицы могут требовать ручной проверки. Формулы, нарисованные картинками, не превращаются автоматически в исполняемый код. Калькулятор поддерживает формулы, явно реализованные в `formula_engine.py`; для неподдерживаемого расчёта или недостаточных данных он должен просить уточнение. Перед применением нормативного ответа проверяйте найденную редакцию документа и область её применения.

Конфликтующие температуры и Δt, несовместимые единицы и неоднозначная длина/расход требуют уточнения. Запрос диаметра трубы не подменяется расчётом вентиляции. Для нескольких пользователей публичного Space изоляция общей истории и mutable-ресурсов пока не подтверждена; локальная проверка не заменяет эту проверку или Docker-сборку.
